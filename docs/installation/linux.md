# Linux 安装与使用 Paxora

**确认架构 → 下载 `.deb` → 安装并登录 → 选择节点 → 连接。**

## 系统与架构

当前发布面向 **Ubuntu 24.04 GNOME 桌面**，支持 X11 和 Wayland 会话，提供 x86_64（amd64）与 arm64 两种架构的安装包。其他发行版或桌面环境尚未列入本教程的支持基线；不要把 `.deb` 能被解压等同于系统兼容。

在终端确认架构：

```bash
dpkg --print-architecture
```

| 输出 | 应选择的安装包 |
| --- | --- |
| `amd64` | 文件名以 `-amd64.deb` 结尾的包，对应 x86_64 |
| `arm64` | 文件名以 `-arm64.deb` 结尾的包 |

两种架构不能混装。日常使用需要本机正常登录的图形桌面会话，以及安装、更新和卸载时的管理员授权。

## 下载地址

- [官方下载目录](https://vault.digitalage.services/index.php/s/E8srJpTGLgQNzW7)
- [备用下载目录](https://vault.paxoras.com/index.php/s/E8srJpTGLgQNzW7)

进入 **Paxora-Linux** 文件夹，按架构下载正式版 `.deb`。文件名包含版本与架构；首次使用不选择带 `test`、`debug` 标记的测试或诊断包。

后续双架构发行使用统一版本号，分别下载匹配的安装包。2026.1019 首发的两个架构版本号不同属于历史记录，不能靠版本尾号判断架构。

## 安装与首次连接

1. 在保存安装包的文件夹中打开终端。
2. 使用下面的命令安装，将示例文件名替换为实际下载的文件名：

   ```bash
   sudo apt install ./Paxora-linux-版本-amd64.deb
   ```

   arm64 设备选择对应的 `-arm64.deb` 文件。`./` 表示安装当前目录的文件；安装期间按系统提示输入管理员密码，并检查依赖安装结果。
3. 从桌面的应用列表打开 **Paxora**，使用普通用户启动，不要用 `sudo` 运行客户端。
4. 登录自己的账号，等待套餐和节点同步完成。
5. 选择节点和连接方式，再点击连接；状态显示已连接后确认所需应用能正常使用。

Linux 提供系统代理与虚拟网卡两种方式。系统代理主要供遵循桌面代理设置的应用使用；需要更广泛的应用流量接管时可使用虚拟网卡。完整 `.deb` 已包含所需助手，不要通过手工提权或关闭系统安全机制替代正常安装。

不用时先断开连接，等待状态恢复为未连接，再退出 Paxora。

## 更新

在客户端设置中检查更新，按提示下载并安装。安装阶段需要系统管理员授权，完成后客户端会重新打开。关闭自动更新后仍可手动检查更新。

也可从上面的官方下载目录取得同一架构的新版 `.deb`，先断开并退出客户端，再用 `sudo apt install ./实际安装包.deb` 安装。不要为了升级而删除个人配置。

## 卸载

先断开连接并完全退出客户端。在系统的软件管理器中卸载 Paxora；也可先从安装包读取实际包名：

```bash
dpkg-deb --field ./实际安装包.deb Package
```

然后使用 `sudo apt remove 包名`，将“包名”替换为上一条命令显示的值。安装包文件名和系统包名可能不同，不要直接把文件名当成包名。卸载完成后确认普通网络访问已恢复；若系统提示助手停止或网络恢复失败，保留错误信息并反馈，不强制跳过。

## 常见问题

- **提示架构不匹配**：重新检查 `dpkg --print-architecture`，下载同一架构的包。
- **缺少依赖或安装失败**：确认使用 Ubuntu 24.04 GNOME 和 `apt install ./文件名.deb`；保留终端中的具体错误，不反复强制安装。
- **虚拟网卡不可用**：确认安装的是完整 `.deb`，从本机正常登录的图形会话运行；远程或非活动会话不作为虚拟网卡使用环境。
- **连接成功但某个应用不走代理**：先检查该应用是否遵循系统代理；必要时再使用虚拟网卡，避免同时运行其他 VPN 或代理工具。
- **仍然无法连接**：按[无法连接排查](../troubleshooting/cannot-connect.md)操作；仍未解决时通过[问题反馈指南](../support/feedback.md)提供系统、架构、客户端版本、连接方式与错误信息，遮挡账号和订阅地址。
